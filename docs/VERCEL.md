# Переезд на Vercel

План миграции с GoDaddy (Apache + Cloudflare) на Vercel **без изменения рендеринга**:
сайт остаётся статическим (`output: "export"`), Vercel отдаёт ту же папку `out/`,
а всё, что раньше делал `public/.htaccess` (редиректы, выбор локали, заголовки),
перенесено в [`vercel.json`](../vercel.json).

Деплой после переезда — это `git push` в `main`: Vercel сам собирает и публикует.
`scripts/deploy.mjs`, ручной сброс кэша Cloudflare и tar-заливка больше не нужны.

## Почему статика, а не SSR

Сайт сейчас полностью статический — ни одной серверной ручки. Поэтому самый
безопасный переезд: оставить `output: "export"`. Рендеринг гарантированно
1-в-1 тот же, что уже отлажен в проде. Серверные фичи (middleware, ISR,
API-роуты, оптимизация картинок) можно включить позже, убрав `output: "export"`
и вернув логику в `next.config` + `middleware.ts` — но это отдельный шаг,
на переезд он не требуется.

## Шаг 1. Импорт проекта

1. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → выбрать
   `wmsangel/24zdorovie`.
2. Framework — **Next.js** (определится сам). Build Command `npm run build`,
   Output — определяется автоматически (`out/` из `output: "export"`).
3. **Deploy**. Через ~2 минуты будет preview-URL вида `24zdorovie-xxxx.vercel.app`.

Ветку можно указать `vercel-migration` для первого теста или сразу `main` после
мержа — см. шаг 4.

## Шаг 2. Проверить preview (до переключения DNS)

На `*.vercel.app` прогнать:

- `/` → редирект на `/ru/` (или `/en/`, если браузер английский или стоит кука `locale=en`);
- переключатель языка в шапке ставит куку → `/` начинает вести на выбранную локаль;
- открываются `/ru/`, `/en/`, статья, калькулятор, тег;
- `/ads.txt`, `/sitemap.xml`, `/robots.txt`, ключ IndexNow `*.txt`, файлы
  верификации Google/Yandex — отдаются с корня (код 200);
- `/rss` → `/rss/ru.xml`, `/feed` → `/rss/ru.xml`;
- заголовки безопасности на месте (`curl -I` → `X-Content-Type-Options` и т.д.).

## Шаг 3. Домен и DNS (Cloudflare)

Домен на NS Cloudflare, поэтому записи меняются в Cloudflare, а не в GoDaddy.

1. В Vercel: **Project → Settings → Domains** → добавить `24zdorovie.com`
   и `www.24zdorovie.com`. Основным сделать **без www** (www будет редиректить).
2. Vercel покажет нужные записи. В Cloudflare → **DNS**:
   - `A` `@` → `76.76.21.21`
   - `CNAME` `www` → `cname.vercel-dns.com`
   - Прокси Cloudflare (оранжевое облако) для этих записей **выключить** (серое,
     DNS-only): SSL и CDN берёт на себя Vercel. Иначе возможен конфликт сертификатов
     и двойное кэширование.
3. Дождаться, пока Vercel выдаст сертификат (обычно минуты). HTTPS и
   www→apex Vercel делает сам — правил для них в `vercel.json` нет намеренно.

> **HSTS.** В `.htaccess` он был закомментирован. На Vercel включать так же
> осознанно и только после того, как HTTPS точно работает на всех поддоменах.

## Шаг 4. После переключения

```bash
curl -sI https://24zdorovie.com/            | head -5   # 302 → /ru/
curl -sI https://www.24zdorovie.com/        | head -3   # 301/308 без www
curl -sI -H 'Accept-Language: en-US,en' https://24zdorovie.com/ | grep -i location  # → /en/
curl -s  https://24zdorovie.com/ads.txt                          # pub-ID на месте
for u in /ru/ /en/ /sitemap.xml /robots.txt /rss/ru.xml; do
  printf "%s %s\n" "$(curl -s -o /dev/null -w '%{http_code}' https://24zdorovie.com$u)" "$u"
done
```

Дальше — пересдать `sitemap.xml` в GSC/Bing/Yandex не нужно (URL не менялись),
но `npm run indexnow` после первого деплоя не помешает.

## Откат

DNS-переключение обратимо: вернуть в Cloudflare записи на GoDaddy
(A-запись на IP хостинга, включить прокси обратно) — и сайт снова отдаётся
со старого хостинга. GoDaddy при этом не трогаем до тех пор, пока Vercel
не отработает стабильно несколько дней.

## Стоимость

- **Hobby** — бесплатно, 100 ГБ трафика/мес (с запасом под текущий трафик).
  По ToS предназначен для некоммерческих проектов; сайт с рекламой формально
  коммерческий.
- **Pro** — $20/мес, снимает это ограничение и даёт больше лимитов.

Для старта и теста хватает Hobby. GoDaddy можно не продлевать после того,
как Vercel устоится.

## Чем поведение отличается от `.htaccess`

Перенесено полностью: security-заголовки, кэш ассетов, HTTPS, www→apex,
редиректы `/rss` и `/feed`, точечные редиректы регистра тегов, выбор локали
на `/` (кука → Accept-Language → ru).

Сознательно **не** перенесено (незначимо для этого сайта, все внутренние
ссылки идут с префиксом локали):

- **Редирект путей без префикса локали** (`/nutrition/` → `/ru/nutrition/`).
  В `.htaccess` он был подстраховкой. На Vercel аккуратно сделать его в
  `vercel.json` рискованно (можно случайно увести под редирект `ads.txt` и
  ломать AdSense), поэтому если он реально понадобится — лучше через
  `middleware.ts` после отказа от `output: "export"`.
- **Легаси-редирект тегов с пробелом** (`/tag/силовые тренировки/` →
  `/tag/силовые-трени­ровки/`). Точечные редиректы по аббревиатурам-тегам
  перенесены, а общее правило по пробелу — нет: таких URL в индексе единицы.
