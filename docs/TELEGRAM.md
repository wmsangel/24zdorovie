# Автопостинг в Telegram

Скрипт `scripts/tg-daily.mjs` публикует по одной статье в день в каждый
из двух каналов — русский и английский. Порядок — от самой старой статьи
к новой, то есть лента канала повторяет историю сайта с самого начала.

Запускает всё launchd на рабочем Mac (см. [Расписание](#расписание)).

## Первая настройка

Всё, кроме самих каналов, бота и файла с секретами, в репозитории уже есть.
Проверить, на каком шаге вы находитесь: `npm run tg:status` — если он показывает
очередь, но постов нет, осталось пройти шаги ниже.

### 1. Два канала — именно канала, не группы

Канал устроен как вещание: подписчики читают, бот публикует от имени канала.
В группе пост выглядел бы сообщением участника и терялся в переписке.

*Новое сообщение → Создать канал* → название и описание → тип **Публичный**
и `@username`. Нужны два: русский и английский.

Публичный канал проще: в конфиг пойдёт `@username`. Для приватного нужен
числовой `chat_id` — его показывает [@userinfobot](https://t.me/userinfobot),
если переслать ему любой пост из канала; выглядит как `-1001234567890`.

### 2. Бот

[@BotFather](https://t.me/BotFather) → `/newbot` → отображаемое имя →
username бота (обязан заканчиваться на `bot`). В ответ придёт токен вида
`123456789:AAH...`. Это пароль от бота: не в git, не в скриншоты, не в чаты.

### 3. Бот — администратор обоих каналов

Канал → *Управление каналом → Администраторы → Добавить администратора* →
найти бота по username. Из прав достаточно **«Публикация сообщений»**.
Без этого API вернёт `403: not enough rights`.

### 4. Секреты

```bash
cp scripts/.tg.env.example scripts/.tg.env
chmod 600 scripts/.tg.env
```

Заполнить `TG_BOT_TOKEN`, `TG_CHANNEL_RU`, `TG_CHANNEL_EN`.
Файл в git не попадает (см. `.gitignore`).

### 5. Проверка вхолостую

```bash
npm run tg:status   # что в очереди и сколько уже опубликовано
npm run tg:dry      # показать тексты постов, ничего не отправляя
```

### 6. Первый реальный пост

```bash
npm run tg
```

Посмотреть в канале глазами: подтянулась ли большая картинка-превью, кликается
ли ссылка, как выглядят хештеги. Только после этого ставить расписание.

### 7. Темп публикации

Очередь идёт от самой старой статьи к новой. Сейчас настроено два поста в сутки
на локаль (10:00 и 19:00) — при сотне статей канал догонит свежие материалы
примерно за семь недель. Разово ускориться — `npm run tg -- --count=3`,
насовсем — правкой `StartCalendarInterval` в plist.

## Расписание

```bash
cp scripts/com.24zdorovie.tg-daily.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.24zdorovie.tg-daily.plist
```

Управление:

```bash
launchctl list | grep 24zdorovie             # загружен ли агент
launchctl start com.24zdorovie.tg-daily      # запустить прямо сейчас
launchctl unload ~/Library/LaunchAgents/com.24zdorovie.tg-daily.plist
tail -f tg-daily.log                         # что происходило
```

Время публикации — **10:00 и 19:00**, задаётся массивом `StartCalendarInterval`
в plist. За каждый запуск уходит по одному посту в канал, то есть два поста
в сутки на локаль. Поменять частоту — добавить или убрать `<dict>` в этом массиве
и перезагрузить агента (`unload` + `load`).

Пропущенные запуски launchd не копит: если Mac проспал оба времени, после
пробуждения будет один запуск, а не два. Наверстать — `npm run tg -- --count=2`.

> **Путь к node прибит абсолютным.** launchd не читает профиль оболочки и про
> nvm ничего не знает, поэтому в plist указан полный путь к текущей версии.
> После обновления node в nvm путь надо поправить — актуальный покажет
> `which node`. Симптом поломки: в `tg-daily.log` тишина, в канале пусто.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run tg:status` | Сколько опубликовано, что следующее в очереди |
| `npm run tg:dry` | Показать тексты постов, ничего не отправляя |
| `npm run tg` | Отправить по одному посту в каждый канал |
| `npm run tg -- --locale=ru` | Только русский канал |
| `npm run tg -- --count=3` | Три поста подряд — догнать пропуски |

## Как устроена очередь

Опубликованное запоминается в `.tg-state.json` в корне проекта —
**списком слагов, а не счётчиком**. Отсюда полезные свойства:

- пропущенный день сдвигает график, но ничего не теряет;
- новые статьи встают в конец очереди и не ломают порядок старых;
- состояние пишется после каждого поста через временный файл,
  поэтому падение на втором посте не отменяет первый;
- при ошибке отправки состояние не трогается вовсе — на следующий день
  скрипт повторит ту же статью, а не проглотит её.

Черновики (`draft: true`) в очередь не попадают.

Файл состояния в git не хранится. Если он потеряется, скрипт начнёт
с самой первой статьи заново — при переустановке системы или переезде
на другую машину его стоит перенести руками.

## Формат поста

```
🥗 Питание

Как читать этикетки продуктов и не попадаться на маркетинг

Состав важнее лицевой стороны упаковки: как читать список
ингредиентов, что скрывают надписи «лёгкий» и «без сахара»...

#этикетки #маркировка #состав_продукта

https://24zdorovie.com/ru/nutrition/kak-chitat-etiketki/
```

Эмодзи и название рубрики берутся из `src/config/categories.ts` — скрипт
разбирает файл регуляркой и падает, если формат изменился. Заголовок и
описание — из frontmatter статьи. Хештеги — первые три тега, приведённые
к безопасному виду (пробелы и дефисы → `_`).

Ссылка отдаётся с `prefer_large_media` и `show_above_text`, поэтому Telegram
показывает большую OG-картинку рубрики над текстом. Если картинки в превью
нет — проверьте, что `og:image` статьи не отдаёт 404
(см. [DEPLOY.md](./DEPLOY.md#4-проверка-после-заливки)).

## Оригинальные посты (не только репосты статей)

Кроме репостов статей лента подмешивает вечнозелёные посты — разборы мифов и
короткие советы из `scripts/tg-evergreen.json`. Чередование задаёт
`EVERGREEN_EVERY` в скрипте: при `2` это 1:1 (статья ↔ оригинал), то есть ровно
**один пост со статьёй в слот** — так очередь статей тратится медленно. Оригиналы
**цикличны**: набор идёт по кругу (`everCount % длины`), поэтому лента не
оголяется, даже когда статьи в очереди кончатся.

Формат записи в `tg-evergreen.json` (массивы `ru` и `en`):

```json
{ "id": "ru-uникальный", "title": "🧬 Заголовок с эмодзи",
  "body": "2–3 предложения пользы.", "tags": ["тег1","тег2"],
  "link": "/ru/weight/slug" }
```

`id` — любой уникальный (для порядка и отладки). Публикации считаются счётчиком
`evergreenCount` в `.tg-state.json`, а не списком — набор цикличен. `link`
необязателен: с ним под постом даётся ссылка на профильную статью/инструмент и
большое превью, без него — просто текст. Добавить пост = дописать объект в
массив; порядок массива = порядок публикации в цикле.

`npm run tg:status` показывает обе очереди — и статьи, и оригиналы.

## Если что-то сломалось

| Симптом | Причина |
| --- | --- |
| `403: not enough rights` | Бот не админ канала или без права публикации |
| `400: chat not found` | Опечатка в канале; для приватного нужен числовой `chat_id` |
| `401: Unauthorized` | Неверный токен в `scripts/.tg.env` |
| Пост не ушёл, лог пуст | Mac был выключен, либо сменился путь к node в plist |
| Очередь начала сначала | Потерян `.tg-state.json` |
| `429` | Лимит частоты; скрипт сам ждёт и повторяет |
